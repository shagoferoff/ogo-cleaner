# Старі адреси статей — розширення 1.25.0

Оновлена наявна операція `legacy_urls` («ОГО — старі URL → актуальні»).
Попередній механізм приймав лише точний /articles/view/дата/ID.html,
правильну календарну дату й основний домен ogo.ua. Успіх інсталяції
плагіну не означав, що нетипові адреси оброблялися.

## Визначення ID

Допускаються відсутній /view/ (якщо є дата), .html/.htm, html без крапки,
відсутнє розширення, кінцева крапка та відомі форматувальні домішки
(пробіли, Unicode-розділювачі, закодований <br>). Дата в старій адресі
не визначає ціль — редакція підтвердила збереження ID WordPress.

Вкладені та склеєні URL розділяються лише за відомими OGO origins.
Кожен сегмент повинен бути впізнаною адресою статті або залишком
датованого префікса. Усі знайдені ID мають збігатися; вибір останнього
числа з довільного рядка не використовується. Різні ID, довільні суфікси,
параметри URL та некоректні діапазони залишаються для ручної перевірки.

Автоматичні відповідники дозволені лише для ogo.ua, mail.ogo.ua,
gazeta.ogo.ua, їхніх www-варіантів і адрес від кореня. Виправлення mail
та gazeta погоджені редакцією. Інші внутрішні піддомени, зокрема lt та
catalog, відображаються для перевірки без автоматичного припущення,
що їхні ID належать основному сайту. Зовнішні домени не змінюються.
HTTP-запити й переходи за старими адресами не виконуються.

## Перевірка цілі

Через get_post(ID) перевіряються тип post, publish, відсутність пароля
та публічна доступність. get_permalink повертає внутрішню адресу того
самого головного сайту без параметрів; старі namespaces articles,
woman та nashregion не використовуються як нові цілі.

Причини невдач містять ID і розрізняють відсутній запис, інший тип,
неопубліковану статтю, пароль, недоступність і невідповідний permalink.
Будь-який необроблений збіг переводить матеріал у ручну перевірку,
навіть якщо інші посилання в ньому можна виправити. Автовидалення немає.

Змінюється лише href; текст, інші атрибути й HTML зберігаються.
#page-top прибирається, інші фрагменти зберігаються. Перед застосуванням
кеш відповідників очищається, доступність і permalink перевіряються
повторно та порівнюються з попереднім переглядом. Діють наявні захист
від одночасних правок і журнал точного відкату.

Строгі формати статей в окремих операціях woman/nashregion не змінені;
спільна перевірка доступності цілі тепер повертає докладні причини.
Ревізія використовує оновлений детектор namespace articles.

## Перевірки

У PHP-тестах є всі 14 прикладів редакції; додатково — відсутнє розширення,
помилкова дата, Unicode-пробіли, повтори однакового ID, різні ID,
довільні сторонні вставки, захищені й відсутні записи, HTML-пастки,
збереження тексту та повторний запуск. Сценарії без результату залишають
оригінал; автоматичне вгадування відсутнього запису не виконується.

Локальний WordPress 6.8.3 / MariaDB перевіряє ID 131461 із наданим
редакцією slug великоднього кошика (тестова стаття у власній тестовій
базі), попередній перегляд, застосування трьох пошкоджених URL,
пропуск відсутніх/змішаних/неоднозначних матеріалів, точний відкат,
перейменування й зняття цілі з публікації між скануванням і застосуванням.
Це не перевірка фактичної наявності статей у робочій базі ОГО.

Додатково проаналізовано нормалізовані адреси зі старого CSV ревізії:
для 1294 із 1347 груп (1992 входження) визначається однозначний ID;
49 груп (56 входжень) мають невпізнану структуру, 4 групи (4 входження)
належать іншим підпроєктам. Це лише розбір URL; зведений CSV не містить
усіх оригінальних href і не доводить доступність цілей. Остаточні
підрахунки готових замін дасть нове сканування на робочому сайті.
