# Відсутні статті: очищення — 1.26.0

Окрема операція `legacy_missing`, у меню «ОГО — відсутні статті: очищення».
Використовує той самий журнал зі знімками до/після, права, блокування,
порційне застосування та відкат, що й решта операцій. Потрібне нове сканування.

Спочатку визначає однозначний ID за правилами `legacy_urls` для старих
`/articles/view/…` і `/articles/дата/ID…`. Домени та допустимі спотворення
описані у [legacy.md](legacy.md). Наявні публічні статті отримують актуальний
URL. Видалення дозволене лише коли `get_post(ID)` не знаходить запису і
немає помилки читання БД. HTTP-запитів немає: сам HTTP 404 нічого не доводить.
Наявні чернетки, приватні, заплановані, захищені, кошик та інші типи записів
залишаються для перевірки.

Якщо ціль відсутня:

- У реченні видаляє лише відкривальний і закривальний теги `a`.
  Увесь текст, вкладене текстове оформлення та сторонні посилання зберігає.
- Самостійний `p` або `div` лише з одним таким посиланням видаляє цілком,
  разом із простими обгортками `span/font/strong/b/em/i/u/s/small`, пробілами
  й NBSP. Більші контейнери з іншим вмістом не видаляє.
- Окремий рядок з одним посиланням і текстовими обгортками також може
  видалятися. Межі: початок/кінець контейнера, `br`, блоки або порожній рядок.
  Один кінцевий `br` забирається разом із рекомендацією.
- Додатковий текст, інші посилання, медіа, коментарі та нестандартні теги
  заважають видаленню цілого блоку. Текстове посилання тоді знімається;
  медіа всередині самого посилання залишається для перевірки.
- `id`/`name` контейнерів зберігаються; посилання з власним `id`/`name`
  потребують перевірки. Скрипти, стилі, коментарі, pre/code/textarea пропускаються.
  Неврівноважені або вкладені посилання й інший пошкоджений HTML — вручну.

`/archive/…/site/…` завжди ручна перевірка. Приклад ID 33708 показав, що
наявна стаття за таким ID може не відповідати анкору. Новий формат не додається
до автоматичного визначення ID або до старого режиму заміни. Пошук схожих
назв/дат/переглядів та вибір заміни автоматично не виконуються.

Журнал показує окремо замінені URL, зняті посилання, видалені блоки,
відсутні ID та причини ручної перевірки. Матеріал із хоча б одним необробленим
збігом не стає готовим до масового застосування. У попередньому перегляді
можна побачити часткові пропозиції, але вони не застосовуються до такого матеріалу.

Перед кожним застосуванням очищає кеш резолвера та повторює аналіз оригіналу.
Відновлений після сканування запис, зміна публічності або permalink цілі
блокують застаріле очищення. Атомарний запис також перевіряє оригінальний
контент, дату модифікації, статус і тип вихідного матеріалу. Відкат відновлює
точні вихідні байти і не перезаписує подальші редакторські зміни.

Перевірки: `tests/missing.php` містить усі десять редакційних випадків,
збереження іншого вмісту, неоднозначні URL, помилки БД та повторні запуски.
`tests/missing-wordpress.php` запускається тільки на ізольованій базі
`ogo_audit_test`: сканування, справжнє застосування, відкат, ручні випадки,
поява цільового запису та конкурентні правки джерела.
