# Архівні та відсутні статті

Операція «ОГО — відсутні статті: очищення» працює з основним текстом
(`post_content`). Після оновлення до 1.31.0 почніть нове сканування.

| Адреса | Дія |
| --- | --- |
| `/archive/РРРР-ММ-ДД/розділ/число` | Зняти теги посилання |
| `/rubrics/рубрика/РРРР-ММ-ДД/число` | Зняти теги посилання |
| Старі `/articles/view/…` і `/articles/дата/ID…` | Знайти ID у WordPress. Замінити URL наявної доступної статті або зняти теги посилання, якщо запис відсутній |

Архівні адреси можуть бути абсолютними, від кореня сайту або починатися з `//`.
Кінцевий слеш необовʼязковий. Числа з архівних адрес не шукаються в базі.
Активні рубрики `/rubrics/view/…` та сторонні домени пропускаються.

Після зняття тегів `a` залишаються текст, вкладені зображення й оформлення,
зокрема коли посилання займає весь абзац. Коментарі, скрипти, стилі й блоки
коду пропускаються.

Домени й варіанти старих адрес `/articles/…` описані в [legacy.md](legacy.md).
Чернетки, приватні, заплановані й захищені записи, кошик, інші типи записів
та неоднозначні адреси потребують ручної перевірки. Помилка бази або HTTP 404
не підтверджує відсутність статті. Матеріали з необробленими збігами чи
пошкодженою розміткою залишаються для ручної перевірки.

Перед застосуванням плагін повторно перевіряє доступність статті та permalink.
Запис і відкат перевіряють збережений контент, дату редагування та статус,
щоб не перезаписати чужі правки.

Перевірки містяться у `tests/missing.php` і `tests/missing-wordpress.php`.
Другий тест потребує ізольованого WordPress із базою `ogo_audit_test`.
