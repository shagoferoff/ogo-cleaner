# Аналіз OGO Tag Manager 3.7.0

Вихідну версію імпортовано без змін із ogo-tag-manager-v3.7.0.zip. Це аналіз коду, без запуску WordPress і без змін на сайті.

## Однина → множина

`groups()` групує лише назви з однаковим нормалізованим написанням. `stem()` використовує короткий префікс для підказок; він не визначає граматичну множину. Тому адвокат → адвокати та безпілотник → безпілотники не є повноцінним окремим сценарієм.

`execute_one()` уже додає цільову позначку всім пов’язаним об’єктам джерела. Наявні зв’язки з ціллю повторно не додаються. Джерельна позначка та її зв’язки залишаються до окремого видалення. Є знімок стану, журнал і перевірка зв’язків.

Бажаний інтерфейс: список пар «джерело → множина», кількість статей і вибір цілі. Приклад: адвокат (#5681) → адвокати (#7058). Після перегляду вибраних пар одна дія запускає потрібні перевірки, перенесення й перевірку результату та дає CSV редиректів. Видалення джерел виконує користувач окремо. Назви з однаковим префіксом не можна автоматично вважати граматичними парами; потрібні перевірені відповідності й перегляд неоднозначних пропозицій.

## Кириличні slug

Наявний сценарій: вибір до 50 позначок → підготовка пакета → підтвердження → зміна slug → окремий CSV → ручний імпорт у Redirection → перевірка URL. Транслітерація вже є у `suggestion()`, а `slug_apply()` зберігає ID позначки та її зв’язки. Кирилиця може зберігатися percent-encoded, тому відбір має перевіряти й декодований slug.

Бажаний інтерфейс: «Знайти всі кириличні slug» → таблиця «було → стане» з автоматичною транслітерацією → «Застосувати». Обробка всього списку невеликими пакетами, з прогресом і продовженням. Зайняті або порожні slug пропускати з поясненням. Назви позначок залишаються українськими.

## Редиректи

`redirect_csv()` і `slug_csv()` експортують рядки source,target,0,301 без заголовка. Вони не активують правила. Між зміною slug й імпортом CSV старий URL може перестати працювати.

Для вимоги «перейменувати й зробити редирект» потрібен механізм активації 301, узгоджений зі зміною slug: інтеграція з установленим Redirection або власний перевірений обробник. Самого CSV недостатньо. Треба перевіряти дублікати, цикли, ланцюжки, чинність цілі й поведінку відкату. При об’єднанні та наступній зміні slug цілі всі старі URL мають вести прямо на остаточну адресу.

## Послідовність наступних правок

1. Додати простий сценарій однина → множина поверх наявного механізму перенесення, з ручним видаленням джерел.
2. Спростити масову транслітерацію кириличних slug та узгодити її з активацією 301.
3. Перевірити збереження зв’язків, зайняті slug, повторний запуск, часткові помилки, відкат, прямі 301 та HTTP 200 цілі на тестовому WordPress.

Документація архіву описує стару поведінку й не є новими вказівками користувача. Програмний код у цьому коміті не змінено.
