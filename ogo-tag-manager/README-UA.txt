OGO TAG MANAGER 3.8.0 — НОВІ ШВИДКІ ДІЇ

ОНОВЛЕННЯ
WordPress → Плагіни → Додати новий → Завантажити плагін → ogo-tag-manager-v3.8.0.zip.
Замініть установлену версію 3.7.0. Архів має той самий каталог ogo-tag-manager.
Після оновлення відкрийте Інструменти → OGO Tag Manager без старого параметра tab у посиланні.
Нова головна сторінка називається «OGO Tag Manager 3.8 — швидкі дії».
Збережені рішення, перенесення та пакети slug попередніх версій не очищуються.

1. ОДНИНА → МНОЖИНА
Натисніть «Знайти пари». Модуль пропонує прості мовні відповідності: адвокат → адвокати, безпілотник → безпілотники тощо.
Це пропозиції, не повний словник української мови. Нерегулярні та неоднозначні форми перевіряйте вручну.
Відсутню пару можна додати за ID джерела й цілі.
Виберіть пари → «Перевірити й об’єднати вибрані» → перегляньте адреси, кількість нових зв’язків і попередження → підтвердіть.
Модуль додає цільову позначку до всіх статей джерела та перевіряє зв’язки. Статті з обома позначками не дублюються.
Джерельна позначка та її зв’язки залишаються. Після перевірки статей ви самі видаляєте джерело штатними засобами WordPress.
На одну пару допускається до 500 нових зв’язків. Для більших пар використовуйте розширену панель.
Власні Yoast title/description/noindex джерела автоматично не переносяться; попередження видно перед підтвердженням.

2. КИРИЛИЧНІ SLUG → ЛАТИНИЦЯ
Натисніть «Знайти всі кириличні slug». Знаходяться також URL-кодовані кириличні slug.
Перегляньте автоматичну транслітерацію та за потреби виправте її.
Виберіть окремі рядки або «Вибрати всі / зняти вибір» → «Змінити вибрані slug та ввімкнути 301».
Кожна позначка обробляється окремим запитом. Є прогрес, результат для кожного рядка і зупинка після поточного запиту.
Назва позначки, ID та зв’язки зі статтями зберігаються. Зайняті, порожні та некоректні slug пропускаються з поясненням.
Після перезавантаження знову знайдіть кириличні slug: успішно оброблені вже не потраплять у список.
Після мережевого збою спершу перевірте журнал у розширеній панелі — запис міг завершитися на сервері.

301 І СПИСОК РЕДИРЕКТІВ
Для нових операцій 3.8 правила створюються автоматично. Вручну імпортувати CSV у Redirection не потрібно.
Плагін має залишатися активним, інакше його 301 не виконуватимуться. Для перенесення правил в інший інструмент є спільний CSV.
Правила працюють для точних старих адрес архіву позначки, GET і HEAD. Адреси пагінації /page/2/, фіди та довільні query-параметри окремо не мігруються.
Потрібні звичайні красиві посилання WordPress. Адреси виду /?tag=... для цього інструмента не підтримуються.
Редиректи зберігають ID цілі: подальша зміна її slug веде старі адреси відразу на актуальну адресу.
Після ручного видалення джерельної позначки правило зберігається. Якщо її старий slug отримала інша позначка, правило не перехоплює нову адресу.
Список активних правил показано внизу швидкої сторінки після її оновлення. CSV: source,target,0,301; без заголовка та BOM.
Старі пакети 3.7 автоматично не активуються: для них залишається попередній імпорт у Redirection.
Наявні зовнішні редиректи та серверний/CDN-кеш можуть спрацювати раніше за WordPress. Після тесту за потреби очистіть кеш і перевірте стару адресу.

ВІДКАТ
«Розширена панель і відкат» → «Перевірка slug» → потрібний пакет → «Відкотити slug».
Відкат доступний лише за умов попередніх захисних перевірок. Теги з перенесеннями можуть вимагати ручної перевірки.
Повернення старого slug автоматично вимикає непотрібне правило цього плагіна.
Відкат перенесення доступний у попередній черзі, поки джерело існує й контрольний відбиток не змінився. Після успішного відкату його правило вимикається.
Окремо імпортовані у Redirection правила потрібно прибирати вручну.

16 браузерних та HTTP-перевірок: справжній JavaScript і PHP-обробники на локальному сервері зі штучною базою позначок; підтвердження/скасування, перенесення, slug, 301, HEAD/POST, CSV, зупинка та відсутність помилок JavaScript.

НИЖЧЕ — ІСТОРИЧНА ДОКУМЕНТАЦІЯ 3.7 (для розширеної панелі; нові швидкі дії описано вище)

OGO Tag Manager 3.7.0
Оновлення на основі 3.6.0 — 26 жовтня 2026 року

ВСТАНОВЛЕННЯ
Зробіть резервну копію бази та збережіть ZIP 3.6.0.
У WordPress: Плагіни → Додати новий → Завантажити плагін → вибрати ZIP 3.7.0 → замінити поточну версію.
Папка та головний файл залишилися ogo-tag-manager/ogo-tag-manager.php.
Тепер ZIP також містить includes/ та assets/: потрібно оновити всю папку, а не лише головний PHP-файл.
Формат і ключі старої черги, контрольних знімків, перенесень та журналу збережені. Стара черга не очищається.
Нова історія пакетів slug зберігається окремо.

ЗМІНА SLUG
Інструменти → OGO Tag Manager → Перевірка slug.
Позначте 1–2 теги для першого запуску. За потреби виправте запропонований латинський slug.
Натисніть «Перевірити вибрані» й перегляньте результат.
Якщо slug зайнятий, рядок буде заблокований і покаже наявний тег: перевірте об’єднання у «Дублікатах».
Позначте підтвердження показаного плану та натисніть «Змінити перевірені slug».
Обробляються тільки готові рядки, по одному запиту на тег. Пакет — до 50 тегів.
Після виконання відкрийте «Пакети змін slug» та завантажте CSV конкретного пакета.
Імпортуйте файл у Redirection. Формат: source,target,0,301; без заголовка, без BOM.
Натисніть «Перевірити URL пакета»: очікується прямий 301 зі старої адреси та HTTP 200 на новій.
Перевірка URL робить серверні HTTP-запити до власного сайту; хостинг або захист можуть їх блокувати.
CSV не створює редиректів самостійно. Між зміною slug та імпортом старі URL можуть бути недоступними.

ПАКЕТИ, ПРОДОВЖЕННЯ ТА ВІДКАТ
«Зупинити після поточного» завершує поточний запит і припиняє запуск наступних.
Після звичайного переривання сторінку можна відкрити знову: пакет має кнопку «Переглянути та продовжити».
Повторне виконання успішного запису не змінює тег вдруге.
Якщо запит перервався безпосередньо під час запису, стан «Перервано під час запису» потребує ручної перевірки. Автоматичний повтор такого рядка заблокований.
«Відкотити slug» повертає старий slug лише якщо поточний стан збігається з виконаною зміною, старий slug вільний і тег не бере участі в перенесенні.
Якщо редирект уже імпортовано, після відкату окремо приберіть або змініть це правило в Redirection.
CSV містить тільки успішні, не відкочені зміни. Якщо після виконання адреса змінилася, експорт блокується.
Повторний імпорт того самого CSV контролюйте засобами Redirection для обробки дублікатів.

ДУБЛІКАТИ Й ЧЕРГА
Рішення, скасування та додавання груп до черги зберігаються через AJAX.
Інтерфейс відновлює розгорнуті групи, вибрані цілі, прапорці та положення відносно робочого елемента.
Підказки пошуку завантажуються після відкриття групи, а не одразу для всіх згорнутих груп.
У групі можна вибрати «Основний тег для пакетного відбору». Сервер перевіряє належність цілі до групи.
Цей перемикач стосується верхньої кнопки «Додати вибрані групи до черги».
Окрема кнопка «Усю групу в чергу» має власний підпис із фіксованою запропонованою ціллю; індивідуальні рядки теж мають власний вибір.
У «Черзі рішень» є прапорці та кнопки повторної перевірки вибраних / усіх перенесень, у тому числі тих, що раніше мали OK.
Прогрес і помилки показуються під час роботи; перевірку можна зупинити після поточного запису.
«Не об’єднувати» більше не виключає відповідний тег із підказок автору.

ОБСЯГ ЦІЄЇ ВЕРСІЇ
Виконання об’єднань і видалення залишаються окремими підтверджуваними діями.
Ліміти старого перенесення збережено: одна ціль, до 5 джерел і 500 нових зв’язків на пакет.
Автоматичне створення правил у Redirection та перебудова всіх вкладок не входять у 3.7.0.
Штатна зміна slug зберігає ID тегу; модуль не переносить і не видаляє зв’язки статей у цьому сценарії.
Інші встановлені плагіни можуть реагувати на зміну тегів своїми обробниками WordPress.

30 ізольованих перевірок логіки пройшли: конфлікти, дублікати в пакеті, застарілий план, збереження зв’язків/даних, повторні запити, часткове виконання, продовження, відкат, повторна перевірка зв’язків, блокування конкурентного запису.
9 перевірок взаємодії DOM із PHP-обробниками пройшли: підтвердження, AJAX-рішення, вибір основного тегу, відновлення розгорнутих груп, відкладений пошук, точний CSV, відкат.
Ці перевірки використовували ізольовані замінники API WordPress. Справжній WordPress/MySQL, Yoast та Redirection у цьому середовищі не запускалися.
Повноцінну перевірку геометрії прокручування в браузері виконати не вдалося через обмеження середовища. На сайті перевірте положення екрана на короткій і довгій сторінці.
Рекомендований перший тест: 1–2 зміни slug → CSV → імпорт → перевірка URL; потім одна група дублікатів.
