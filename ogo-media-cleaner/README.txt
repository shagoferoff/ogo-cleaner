OGO cleaner, версія 1.19.0

Оновлення:
1. Зробіть актуальну резервну копію бази даних.
2. Плагіни → Додати → Завантажити плагін.
3. Виберіть ogo-cleaner-1.19.0.zip і підтвердьте заміну встановленого
   плагіна. Каталог і головний файл залишилися тими самими.

5. Виберіть потрібний проєкт / операцію, натисніть «Відкрити».
6. Натисніть «Нове сканування», залишайте вкладку відкритою до завершення.
7. Перевірте «Було → стане» на кількох матеріалах. Спочатку очистіть
   вибрані, перевірте їх на сайті, потім можна очистити всі готові.
8. Очистіть кеш сайту/CDN, якщо використовуються.

Нове у 1.19.0 — Наш регіон: заміна URL:
Додано окрему операцію «Наш регіон — заміна URL».
14 рубрик /nashregion/rubrics/view/… замінюються на теги за картою
з експорту WordPress; назви slug не виводяться автоматично з транслітерації.

https://ogo.ua/rubrics/view/region/ — «Новини Рівного».

параметри та інші якорі залишаються. Підтримано http, https, www, //,
адреси від кореня сайту та кінцевий слеш.

невалідні дати/ID, відсутні записи, статті з параметрами, невідомі рубрики
та пошкоджені посилання залишаються для ручної перевірки.
Якщо є необроблені збіги, матеріал не потрапляє до готових для масової заміни.
Перед застосуванням повторно перевіряється відповідність попередньому перегляду.
У наданому експорті: 116 статей, 113 рубричних посилань та 3 на головну;

Попередні правила збережені. Почніть нове сканування після оновлення.
Фактичний префікс таблиць сайту — wp_; плагін використовує $wpdb->prefix.

Режими «Медіа» та «Медіа — зняття посилань, зберегти текст» тепер

частину посилань, але залишить голий URL, src, коментар або інший
нестандартний фрагмент із доменом.

Нове у 1.12.0 — область сканування custom post types:
Сканування й запис змін тепер охоплюють не тільки стандартні post/page,
а й типи rivnenschina, dovidka, phogo, press. Це стосується всіх режимів
плагіна, включно з «Медіа» та «Медіа — зняття посилань, зберегти текст».
Перед застосуванням після оновлення обов'язково зробіть нове сканування:
старі сканування 1.11.0 залишаються в журналі, але для очищення не
використовуються.

SQL для попередньої інвентаризації media.ogo.ua у вмісті записів:

SELECT post_type, post_status, COUNT(*) AS materials
FROM wp_posts
WHERE post_content LIKE '%media.ogo.ua%'
GROUP BY post_type, post_status
ORDER BY post_type, post_status;

Якщо у базі інший префікс таблиць, замініть wp_posts на відповідну
таблицю, наприклад ogo_posts. Плагін 1.19.0 чистить тільки типи post,
page, rivnenschina, dovidka, phogo, press у статусах publish, private,
draft, pending, future.

   після нього, інші посилання та зображення зберігаються для перевірки.
2. Після видалення запрошень виберіть «Медіа — зняття посилань,
   зберегти текст → Відкрити → Нове сканування».

   Незакриті/вкладені один в одного посилання залишає для перевірки.
   Голі URL, інші домени, код та коментарі не змінює. Ця операція сама
   не видаляє запрошення до галерей, тому важлива послідовність 1 → 2.
Режими мають окремі сканування та журнали. Старі журнали залишаються.
За потреби відкат кількох операцій виконуйте у зворотному порядку.
Після оновлення потрібне нове сканування перед застосуванням.

Попередні зміни 1.9.0 — Ustream:
Виберіть «Ustream — видалення плеєрів і підписів → Відкрити → Нове сканування».
Видаляє iframe з точним доменом ustream.tv або www.ustream.tv, src виду
/embed/ID чи /embed/recorded/ID, через http, https або //; параметри src
можуть бути будь-якими. Iframe має бути закритий і містити лише пробіли.
Ширина, висота, стилі, атрибути та їх порядок не впливають на впізнавання.
Видаляє службові посилання на головну Ustream з точним текстом
«Live streaming video by Ustream» або «Video streaming by Ustream».
Просте вкладене оформлення та пробіли в підписі підтримуються.
Інші посилання/згадки Ustream автоматично не видаляє.
Прибирає br/пробіли між видаленим плеєром та видаленим підписом,
прості p та блоки wp:html/wp:paragraph, якщо операція зробила їх порожніми.
Наявні раніше порожні абзаци, текст статей, зображення, інше відео,
код, коментарі, скрипти, голі URL та інші домени зберігаються.
Нестандартні посилання, невпізнані src, непорожній вміст iframe та
незакриті теги залишаються для перевірки. Вміст iframe є непрозорим:
посилання всередині його fallback-тексту не обробляються окремо.
Рахуються елементи Ustream, а не лише посилання: iframe + підпис = 2.
У рядку журналу є окремі числа плеєрів, підписів та порожніх блоків.
Очищення працює частинами з попереднім переглядом і журналом відкату.
Попередні режими та журнали збережено. Перед застосуванням потрібне
нове сканування. Оригінали вже очищених вручну статей не відновлює.

Попередні зміни 1.8.0 — ОГО: старі URL → актуальні:
Виберіть «ОГО — старі URL → актуальні → Відкрити → Нове сканування».
Режим призначений для міграції ОГО, де старий ID став ID WordPress.
Знаходить href виду /articles/view/РРРР-ММ-ДД/ID.html, отримує запис
за цим ID і його актуальну адресу через штатну get_permalink().
Використовує налаштування постійних посилань та фільтри WordPress,
а не складає адресу вручну із post_name. Звичайні http-адреси permalink
переводить у https для ОГО. Підтримує ogo.ua та www.ogo.ua, http/https,
// та адреси від кореня сайту. Посилання інших доменів не обробляє.
Змінює лише значення href, зберігаючи анкор, текст, оформлення, атрибути,
абзаци та вкладені зображення. Фрагмент #section зберігає; голі URL,
?p=ID, метаполя full_text, меню, віджети, код і скрипти не змінює.
Лише доступні опубліковані записи типу post без пароля є цільовими.
Відсутні/неопубліковані статті, параметри ?..., невпізнаний формат,
пошкоджені/вкладені посилання та незвичні permalink залишає для перевірки.
Причини наведено в журналі. Перевірка HTTP-доступності сторінки не
виконується: джерело відповідності — ID і permalink поточного WordPress.
Повторні ID кешує лише в межах поточного запиту; постійної копії slug
не створює. Порції сканування — до 50 матеріалів, заміни — до 20.
Перед застосуванням повторно перевіряє адреси й доступність цільових
записів. Якщо результат відрізняється від попереднього перегляду,
пропускає матеріал із конфліктом; треба зробити нове сканування.
Існуючі редиректи для пошуку, зовнішніх посилань і закладок зберігаються.
Сканування статей не змінює. Оригінали зберігаються для відкату, старі
журнали й режими залишаються. API-ключ та HTTP-запити не потрібні.
На великому сайті залишайте вкладку відкритою. Якщо зупинили сканування,
натисніть «Продовжити сканування», щоб продовжити з останнього курсора.
Перед масовою заміною перевірте кілька вибраних статей на сайті.

Попередні зміни 1.7.0 — ВКонтакте:
Виберіть «ВКонтакте — очищення посилань → Відкрити → Нове сканування».
1. Знімає теги a для точних доменів vk.com і www.vk.com (http, https або //),
   зберігаючи імена, назви груп, авторство фото та джерела. Наприклад,
   «За матеріалами <a href=...>ВИЛКА</a>» → «За матеріалами ВИЛКА».
   Інші домени, зокрема vovk.com, залишаються без змін.
2. У простому списку «Або ж пишіть нам у соцмережах - ...» з одним
   Facebook-посиланням та пунктами ВК прибирає пункти ВК і роздільники.
   Facebook, вступний текст та оформлення зберігає.
3. Видаляє весь окремий абзац «Група зустрічі: vk.com/event...».
4. Видаляє впізнаний окремий абзац конкурсу книг, що починається
   «P.S. Хочете поділитися з нами своєю любов’ю до книг?» і містить
   info@ogo.ua, uliana.tet@gmail.com та пару посилань ВК / Facebook.
   Інші застарілі конкурси за цим правилом не видаляє.
Правила абзаців підтримують просте вкладене оформлення, класичний
редактор, HTML p і блоки paragraph Gutenberg. Наступний текст зберігається.
Посилання з голим URL ВК поза впізнаними шаблонами, складні списки,
незакриті та вкладені посилання залишаються для ручної перевірки.
Код, коментарі, скрипти, голі URL поза a і вбудоване відео не змінює.
Лічильник — кількість оброблених HTML-посилань ВК, а не абзаців.
У журналі окремо показано зняття посилань, списки й видалені абзаци.
Попередні журнали та режими збережено; після оновлення потрібне нове
сканування перед застосуванням. Платний API-ключ для цих правил не потрібен.

Попередні зміни 1.6.0 — Каталог:
Виберіть «Каталог — зняття посилань → Відкрити → Нове сканування».
Для точного домену catalog.ogo.ua через http, https або // знімає лише
відкривальний і закривальний теги <a>. Текст між ними, всі пробіли,
переноси рядків, вкладене оформлення, зображення та абзаци зберігаються
побайтово. Речення й імена/назви компаній не переписуються.
Оформлення/атрибути самого тегу a видаляються разом із ним.
Посилання на інші домени, голі URL, src зображень, коментарі, код,
скрипти й текстові приклади HTML не змінюються.
Незакриті, самозакривальні чи вкладені один в одного посилання
залишаються для перевірки. Лічильник показує зняті посилання.
Порожні абзаци не видаляються навіть якщо посилання було порожнім.
Попередні режими, журнали та послідовний відкат збережено.

Попередні зміни 1.4.0 — Рівне святкове (day.ogo.ua):
Дві окремі операції у списку проєктів / операцій.

«Рівне святкове — заміна URL»:
Спочатку рекомендуємо цей режим. Змінює href:
http://day.ogo.ua/articles/view/2013-09-25/43288.html
→ https://ogo.ua/articles/view/2013-09-25/43288.html
Підтримує http, https і //, посилання в реченнях і окремі посилання.
Зберігає шлях, query, fragment, HTML-екранування параметрів, текст,
оформлення, інші атрибути та решту контенту побайтово.
Змінює лише адресу в HTML-посиланні <a href>, не src медіафайлів,
не голі URL і не коментарі/скрипти/код. Інші шляхи не замінює.
Нестандартні порти або закодований шлях залишає для перевірки.
Не перевіряє існування статті на ОГО чи налаштування редиректів:
це точна заміна адреси за погодженим правилом, а не пошук нової статті.

«Рівне святкове — видалення абзаців»:
Видаляє весь простий абзац/окремий фрагмент із посиланням day.ogo.ua,
включно з навколишнім текстом, наприклад «За матеріалами ...» або
«Цікаві факти про Різдво ...». Це ширше правило, ніж для Медіа/Блогів.
У класичному HTML абзац визначається <p> або порожнім рядком;
у Gutenberg — повним блоком paragraph. Весь вміст такого абзацу
буде видалено, тому обов'язково перегляньте «Було → стане».
Абзаци з адресами /articles/view/, іншими посиланнями, зображеннями,
короткими кодами або складним оформленням не видаляються.
Адреси /articles/view/ не входять у звіт видалення: вони в окремому
режимі заміни URL. Захист діє незалежно від порядку двох операцій.
Кожна операція має окреме сканування і журнал. Відкат збережений.
Структура таблиці у 1.4.0 не змінюється порівняно з 1.3.0.

У режимі Блогів посилання Медіа не видаляються, і навпаки.

Правила для Медіа та Блогів:
Видаляються окремі текстові посилання разом із текстом та порожнім
абзацом. Текст посилання може бути будь-яким: «ЧИТАЙТЕ БІЛЬШЕ»,
назва статті, «Блоги ОГО.ua: ...» тощо.
Враховуються багаторядкові посилання та просте оформлення, зокрема
<a><b>текст</b></a> і <b><a>текст</a></b>.
У класичному редакторі — окремі абзаци/фрагменти; у Gutenberg —
окремі блоки абзаців. Неповне/складне оформлення, зображення, відео
і посилання всередині звичайних речень — для ручної перевірки.

Тільки для Медіа діє додаткове правило окремих закликів
«Більше фото у фотогалереї», «Більше фото — у нашій фотогалереї».
Враховуються регістр, дефіс/тире/двокрапка, у/в, нерозривні пробіли,
переноси рядків та просте оформлення. Текст поряд зберігається.
У Блогах це додаткове правило не застосовується.
Інші порожні абзаци та відступи в усій статті глобально не чистяться.
Решта контенту зберігається побайтово.

Область:
Тільки post_content типів post, page, rivnenschina, dovidka, phogo, press
у статусах publish, private, draft, pending, future. Ревізії, вкладення,
кошик, меню, віджети, метаполя, шаблони, інші довільні типи записів і
файли не змінюються.
Модуль не звертається до зовнішніх сервісів, не потребує API,
не видаляє проєкти й не змінює статус публікації матеріалів.

Сумісність зі старими журналами:
При першому відкритті адміністратором таблиця журналу автоматично
доповнюється колонкою проєкту. Старі рядки отримують значення «Медіа»;
оригінали й результати попередніх проходів не перезаписуються.
Усі старі журнали доступні в режимі Медіа, їх відкат збережено.
Старе поточне сканування Медіа теж залишається. Після оновлення перед
новим очищенням необхідне нове сканування вибраного проєкту.
Якщо користувач бази не має прав на зміну структури таблиці,
модуль покаже помилку й не дозволить очищення.

Запис і відкат:
Зміни виконуються порціями до 20 матеріалів. Закриття вкладки зупиняє
наступні порції; поточна серверна порція може завершитися.
Оригінали та результати збережені в таблиці {префікс}ogo_media_cleanup.
Очищення працює з останнім скануванням вибраного проєкту.
Для відкату виберіть проєкт і запуск у журналі, натисніть «Показати»,
потім кнопку відкату. При повторних очищеннях однієї статті відкотіть
спочатку новіший запуск, потім старіший, навіть між різними проєктами.
Модуль атомарно перевіряє контент, дату зміни й статус перед записом.
Відредаговані або відкриті іншим редактором статті пропускаються.
Після конфлікту не перезаписуйте редакторські зміни: перевірте вручну.
Нові матеріали та зміни після сканування потраплять у нове сканування.

Запис напряму змінює лише контент і час зміни, скидає кеш WordPress.
Хуки збереження статей, автоматична синдикація та індексація сторонніх
плагінів не запускаються. Сторонній пошуковий індекс, якщо він є,
оновіть після обробки. Оригінали зберігає власний журнал, а не ревізії.
Якщо запит обірвався між зміною контенту й оновленням журналу,
наступна спроба може показати конфлікт; оригінал залишається в журналі.

Захист:
Тільки адміністратор з manage_options і правами редагування матеріалу.
Nonce для AJAX-дій, блокування паралельних операцій, перевірка проєкту
та запуску на сервері. Попередній перегляд не виконує HTML статей.
Активація/оновлення не змінює контент записів.
Вимкнення/видалення плагіна не видаляє журнали й не повертає зміни.
Не видаляйте таблицю журналу, доки може знадобитися відкат.

Вимоги: WordPress 6.0+, PHP 7.4+ (цільове середовище PHP 8.2/8.3).
